**How to read it.**

- `fixture` reads the ground truth and is an upper bound. It checks the engine (checks, due dates), not extraction.
- `text` is real extraction (PyMuPDF + regex) on the generated PDFs. Scanned pages have no text layer, so `text` reports them as `uncertain` instead of guessing (rule 3).
- A field counts as correct only on an exact match after normalisation: IDs compared without spaces or punctuation, names case-insensitively, amounts to the paisa. Confidence below 0.6 counts as `uncertain`, never as correct.

## Known limits

- Synthetic layouts are cleaner than real invoices; real-world accuracy will be lower.
- Line items are evaluated through C03/C06 (quantities, rates), not field by field.
- In `text` mode the invoice `irn` is always `uncertain`: the sample invoices print only the first 32 characters (`…`), so the full IRN is not on the page. `due_date_text` is not extracted by the `text` extractor at all, so it is always `uncertain` too. Together these account for every uncertain field on digital invoices.
- The `claude` extractor is not in this report unless run with an API key (`--modes claude`).
- Processing time is measured in-process (no HTTP, no disk upload).
- C14 (duplicate) uses the ground-truth buyer code for its history lookup, so this harness does not test buyer identification. The API resolves the buyer from the extracted GSTIN/name (covered by `backend/tests/test_api.py`).
